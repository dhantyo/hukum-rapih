# Architecture

Git is the source of truth; everything else is generated from it.

```
 government sites ─┐
 Wayback Machine  ─┤  pipeline/ (Python)
                   ├─► download ─► data/sources/manifests/*.jsonl (url, sha256; the PDF is not kept)
                   └─► parse ──► data/**/<id>.txt (Bluebell text) + YAML records
                                          │  git push
                                          ▼
              pipeline export-corpus ──► corpus release (JSON + Pagefind index)
                                          │
                                          ▼
              web/ (Solid 2) ──► Cloudflare Worker + R2, prerendered pages, Pagefind search
```

## Repository

| Path | What | License |
|---|---|---|
| `data/` | Source of truth: texts (Bluebell), YAML records, source manifests. No PDFs. | CC0 |
| `pipeline/` | Python package `hukum_rapih`: BPK import, PDF parsing, Akoma Ntoso | AGPL-3.0 |
| `web/` | Solid 2 reader on a Cloudflare Worker: prerendered law, collection and RUU pages from a corpus release ([decisions 0015-0020](decisions/)). The Astro site and its Pages deploy were removed in PR 2; `web-solid/` was renamed to `web/` in PR 3 | AGPL-3.0 |
| `docs/` | Brief, naming rule, this file, decision records | AGPL-3.0 |

### data/

```
data/
  peraturan/<jenis>/<tahun>/<id>/          one folder per regulation
    <id>.yaml                              title, status, relationships, versions, history
    <id>_<YYYY-MM-DD>.txt                  each text version, dated (Bluebell)
  koleksi/<slug>.yaml                      a named law family: short name, base law, aliases
  ruu/<slug>/
    ruu.yaml                               stages, every known document with provenance
    versions/<doc id>.txt                  draft texts (Bluebell)
  sources/manifests/<host>.jsonl           one line per fetched file
  queue-answers/file-order/<id>.yaml       the agent routine's file order, until applied (decision 0022)
```

Names follow [NAMING.md](NAMING.md).

### pipeline/src/hukum_rapih/

| Module | Job |
|---|---|
| `sources/` | One module per upstream site (`http.py` shared: User-Agent, retries; `wayback.py`). `peraturan_bpk.py` (main source since 2026-11-21) with `bpk_session.py` (Cloudflare: Scrapling browser once, then curl_cffi) and `dharmasastra.py` (archive.org copies of BPK's PDFs, tried first, [decision 0029](decisions/0029-bpk-pdfs-from-the-dharmasastra-archive.md)); `peraturan_go_id.py` (earlier imports; `convert_pdf` is shared) |
| `uploads.py` | Hand-downloaded PDFs (from a GitHub release) → manifest line (sha256) + text |
| `manifest.py` | Source manifest records (sha256 per downloaded file; `archive_url` only on lines from before 2026-11-24) |
| `naming.py` | Id validation (NAMING.md) |
| `records.py` | The schema of a law record (Pydantic, `extra="forbid"`, strict types). `load_record` / `save_record` are the only way to read and write `data/peraturan/**/<id>.yaml`: records stay dicts, `save_record` validates and then dumps the same dict (`allow_unicode`, no key sorting), so a misspelt key or a wrong type fails before anything is written. A new field is added here first |
| `pdf/extract.py` | PDF → cleaned lines (headers, page numbers, footers, signature boxes removed) |
| `pdf/ocr_cache.py` | The engine's raw OCR of each scanned page, kept by the PDF's sha256 + engine + DPI + `OCR_CACHE_VERSION` in `$HUKUM_RAPIH_OCR_CACHE` (default `~/.cache/hukum-rapih/ocr`, `<engine>/<sha256>.json.gz`; `off` disables), so a page is OCR'd once, ever; the spell fix is not cached. Workflows keep it between runs with `.github/actions/ocr-cache` |
| `pdf/ocr_fix.py` | Misread words of scanned pages corrected when a spell check is confident; word lists and shape confusions in `pdf/ocr_rules/` ([decision 0013](decisions/0013-ocr-spell-fix.md)) |
| `pdf/structure.py` | Lines → structural blocks (BAB … Pasal, ayat, huruf/angka, Penjelasan) |
| `akn/bluebell.py` | Blocks → Bluebell text (stored in `data/`) |
| `akn/build.py` | Bluebell → Akoma Ntoso XML (Laws.Africa's `bluebell` parser) |
| `akn/meta.py` | The law's context in the AKN meta block, from its record ([decision 0021](decisions/0021-akn-carries-where-a-law-sits.md)) |
| `relations.py` | Amends / revokes / enacts links from titles, plus the pasal an amending law changes (from its text) → `relationships` in each record ([decision 0008](decisions/0008-law-history.md)) |
| `amendments.py` | An amending law's Pasal I → numbered instructions and the new wording of each pasal (the corpus export reads `split`) |
| `history.py` | The versions of an amended law and every change to its pasal → `history` in its record, recomputed with `relations` ([decision 0010](decisions/0010-versions-and-merged-text.md)) |
| `file_order.py` | The file-order queue of the agent routine (decisions 0022, 0023): writes `queue/file-order/` on the `queue` branch, checks the answers and moves them onto `bpk.file_order`; `files_to_read` in `sources/peraturan_bpk.py` joins the files in that order |
| `cli.py` | `hukum-rapih parse / build-akn (writes XML to check it; the site reads the corpus, not XML) / import-bpk / import-peraturan / reparse-bpk / import-pdf / relations / manifest / collect-queue / apply-answers` |

## Workflows (.github/workflows)

| Workflow | When | What |
|---|---|---|
| `ci.yml` | every push | pipeline lint + tests; build AKN into a temporary folder and validate it against the OASIS schema; `web/` check, types, tests and build (when it changed); actionlint; no PDFs in git |
| `deploy.yml` | push to default branch + manual | export the corpus, build `web/`, upload the release to R2, deploy the Worker preview ([web/README.md](../web/README.md)). The Astro `deploy.yml` (Cloudflare Pages) was removed in PR 2, and its Pages project was deleted on 2026-11-27 |
| `import-bpk.yml` | manual (schedule paused 2026-11-21 until the parser is fixed; normally every 6 h) | `mode: import`: BPK metadata, every PDF's sha256 recorded (the dharmasastra archive's archive.org copy first when its hash matches, Hugging Face mirror if BPK's download fails; nothing is uploaded to archive.org since 2026-11-24), text from BPK's PDF with the current parser, never replacing a text with one that has fewer pasal. `mode: reparse`: texts re-converted from our archive.org copies (hash-checked), no BPK. `only`, `no_text` for samples |
| `parser-regression.yml` | push touching the parser + manual | the regression set (`pipeline/tests/regression.yaml`, fails on any law off) |
| `import-peraturan.yml` | manual (schedule removed 2026-11-21) | import from peraturan.go.id (answers only Indonesian IPs; the Indonesian VPN action was removed 2026-11-24, so it works only when the site lets other IPs in) |
| `import-uploads.yml` | manual | PDFs attached to a GitHub release → manifest line (sha256) + text (`import-pdf`) |
| `queue-collect.yml` | manual | the file-order queue for the agent routine, pushed to the `queue` branch, never to main ([decision 0022](decisions/0022-agent-routine-for-judgement-calls.md)) |
| `apply-answers.yml` | push to main touching `data/queue-answers/**` + manual | the routine's merged answers onto their records, then `import-bpk.yml` for those laws |
| ~~`fetch.yml`, `archive-pending.yml`, `archive-retitle.yml`, `archive-delete.yml`~~ | removed 2026-11-24 ([decision 0014](decisions/0014-no-archive-uploads.md)) | download + upload to archive.org, retitle, delete |
| ~~`probe-bpk.yml`, `explore-bpk.yml`, `probe-bpk-app.yml`~~ | removed 2026-11-24 (last in c3332cfb) | one-off probes: which tool passes BPK's Cloudflare check (Scrapling won, `sources/bpk_session.py`); sample BPK pages (now `pipeline/tests/fixtures/bpk/`); BPK's Android app (never got the APK) |

Where things run: everything recurring runs on GitHub Actions (no Claude session or personal
computer needed). GitHub runners reach DPR files and the Wayback Machine, but peraturan.go.id only while it
lets non-Indonesian IPs in. See [sources.md](sources.md) for what each site answers.
